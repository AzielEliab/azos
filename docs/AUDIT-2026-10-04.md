## 3. Security hardening

### Isolation

- Session files stay under `.azos/` in the directory the operator chose. Purge’s parent denylist includes `/`, `/boot`, `/etc`, `/usr`, `/sys`, `/proc`, `/dev`, and `/root`.
- The local app and `OfflineNode.bind_once` listen on `127.0.0.1` only. `bind_once` returns `public_bind: false`, `mesh_enable: false`, `live: false`, and `mesh_node_live: false` after a loopback `GET /health`.
- `httpget.get_bytes` allows HTTPS, or HTTP only for `127.0.0.1` and `localhost`. It does not bind a socket.
- The package test suite forbids host `subprocess` and `eval`.
- The Worker shell stores strings in KV. It does not spawn a host process. Halt text says the hosted halt stops the overlay session.
- The standing isolation sentence is “single-node security-awareness.” The same sentence says a loopback bind is not the fence.

### What an `AZOS-BOOTED` guest log must not imply

`guest_log_is_boot` and `guest_log_is_path` drop their argument and return false. `carry_path(mock=True, guest_log="AZOS-BOOTED")` and `internet_door` therefore keep `alt_internet_live`, `packet_path_live`, and `booted` false. The tests lock that.

A guest log line `AZOS-BOOTED`, including `AZOS-BOOTED` followed by `AZOS-INSTALLED`, must not be read as any of the following:

- a host kernel or `kernel_base`
- a host boot (`booted` stays false; hardware stays false)
- an operating-system install
- `alt_internet_live` or `packet_path_live`
- a second device or a foreign arrival
- `mail_send` or a public mail transfer
- `mesh_node_live` or a public bind
- a phoenix re-seal of the host
- a loopback fence

The same limit covers a process receipt, a userspace file, and a loopback HTTP answer. Those artifacts are local files or a local socket. The doors return `KERNEL-ABSENT`, `BOOT-ABSENT`, and `MESH-NODE-NOT-LIVE`.

### Phoenix / re-seal

This repository contains the sentence “Phoenix is a local wait and re-seal. That is not a loopback fence.” It appears in `carriers.TAIL`, the README, `SKILL.md`, the homepage, and the Worker `internetSentence()`. There is no `phoenix` function, module, or re-seal routine in the `azos` package or the Worker.

Lumen’s watch is `Event.wait(0.25)` until stop. That wait keeps custody of halt, revoke, and purge. It does not re-seal a host. The dual hash lattice refuses a row whose `live` field is true. That is an offline chain check.

The runtime mesh document, which this Worker proxies, carries `phoenix_lock` text (“local wait / re-seal — no controller hunt; not public hostname resurrection”), `phoenix_local_only: true`, and `neighbor_phoenix: false`. That is the runtime mesh record. It does not set this package’s `booted` or `kernel` flags.

### Attack surface of the remote-shell claim

The product claim is a real remote shell with a closed verb list. The surface that follows from the code:

- **Public session open.** `POST /v1/session` on the Worker issues a token after five text gates (minimum length, banned impact phrases, registered action). CORS allows `*`. The token is the capability for that KV session. The gates are length and an allow-list. They are not a host login.
- **Closed exec.** `POST /v1/exec` and the local shell dispatch the same verb set inside the session vfs. Denied verbs and shell metacharacters fail integrity. Echo is truncated. Writes are capped (`MAX_FILE_BYTES` locally).
- **Shared KV.** Sessions and the hosted lattice (`lattice|azos`) live in the download counter namespace. `POST /v1/lattice` appends a gear and a timeslate for any caller who can POST. That ledger is global to the Worker, not per operator.
- **Mesh forwarder.** `POST /v1/mesh/enable|join|heartbeat|leave|broadcast` is forwarded to the runtime. This Worker copies an `Authorization` or `X-Aziel-Runtime-Token` header into the upstream request. The Worker source does not add its own rate limit. A successful upstream enable changes the runtime mesh session the caller is allowed to change. It does not set `mesh_node_live` on the AZ-OS scope object. The homepage script can call those routes from the browser. The module comment says GET never enables radios by itself.
- **LAN frame during the internet door.** `exchange_mesh` binds two UDP sockets to a detected LAN IPv4 address (not `0.0.0.0`) and waits up to 1.5 seconds. `prove()`, and therefore `azos doctor`, calls that path when a LAN address and a machine id exist. On this read the frame’s bytes matched and both host fields were the same machine id, with `second_device: false`. The socket accepts one datagram on that address for the wait. The published live flags are assigned false after the exchange. The door `code` can still be `PACKET-CARRIED`.
- **Local UI.** Loopback only. Purge requires the typed confirm string `CONFIRM` or boolean true on the API. The CLI purge requires `--confirm`.

`uname`, `id`, and `whoami` report the session. They do not read the host kernel identity.

## Harden gaps

No flag in the product was flipped to close these. They are recorded so a later change can close them without widening a claim.

1. **`GET /v1/prefab` publishes `installed: 25`.** `scopeMeta` lets the caller override the boolean. The sentence on that response still says this is not installed as an operating system. Health still says `installed: false`. A strict reader has to use the boolean on health, or `=== true`, and ignore the prefab count. App-level `installed: true` means a hook record.
2. **`PACKET-CARRIED` while the path is refused.** After a same-machine frame whose bytes match, the internet door can show `code: "PACKET-CARRIED"` with `refused: true` and both live flags false. The contract is the flags and the sentence. The code string is easy to over-read.
3. **The LAN probe runs inside the door check.** `doctor` / `prove` / `report` call `exchange_mesh` when a LAN address and a machine id exist. The bind is that address, for about 1.5 seconds, and it accepts a datagram. Live flags are forced false afterward. The nested `carry` object still echoes `bytes_match` and the host ids. On this read the nested `second_device` stayed false because the ids matched. `_base(True)` would mark the report live if a future caller passed it; `carry_path` does not.
4. **Guest-log helpers ignore the log text.** They return false for every string, which is what the contract requires. The raise branch never sees a true result. The tests are what stop a later patch from treating `AZOS-BOOTED` as a host boot.
5. **Install marker wording.** `place()` writes `Installed AZ-OS.` and returns `installed: false`.
6. **Phoenix is a sentence in this tree.** The runtime mesh record has phoenix fields. This package has no re-seal routine. The sentence must not be read as evidence that a guest boot log re-sealed the host.
7. **Mesh prose and mesh proxy diverge.** Module constants and the skill say default off, no node gate, no auto-heal, and not anonymity. The forwarded runtime document at this read said otherwise. `mesh_node_live` stayed false. The constants are not applied to the proxied JSON.
8. **Hosted lattice and session share the download KV, with CORS `*`.** Session open is the five text gates. Lattice append is unauthenticated. Mesh POSTs are forwarded with the caller’s bearer. That is the remote-shell and proxy surface. It is not a host shell.
9. **Catalog sha and DOI sit outside this commit.** The runtime card sha is not in this clone. The runtime product page cites a DOI this tree refuses. Local flags were not updated to match either artifact.
10. **“kernel-overlay” in the lattice comment** and **MirageGrid’s VPN hook line** use stronger words than the flags. The flags stay `kernel: false` and `vpn: false`.
